# Seraph — магазин луп-китов

Готовый сайт на Next.js 14 (App Router) + Tailwind: витрина, карточки товаров, страница товара,
корзина (хранится в localStorage браузера) и оформление заказа через Stripe Checkout с выдачей
файлов после оплаты.

## Структура

- `app/page.tsx` — главная страница
- `app/loops/page.tsx` — каталог
- `app/product/[slug]/page.tsx` — карточка товара
- `app/cart/page.tsx` — корзина
- `app/checkout/success/page.tsx` — страница после оплаты со ссылками на скачивание
- `app/free/page.tsx` — бесплатный кит за почту
- `app/admin` — панель администратора (пароль, товары, лиды)
- `app/api/checkout` — создаёт сессию Stripe Checkout, применяет скидку за объём
- `app/api/session` — проверяет оплату для страницы успеха
- `app/api/download` — проверяет оплату и отдаёт реальную ссылку на файл
- `app/api/webhook` — (опционально) для email-уведомлений после оплаты
- `app/api/admin/*` — API админки (продукты, бесплатный кит, лиды) — защищены cookie-сессией
- `lib/store.ts` — единая точка чтения/записи товаров и ссылок на файлы (Redis, с fallback на seed-данные)
- `lib/seed-data.ts` — стартовый набор товаров, используется пока не подключён Redis
- `lib/leads.ts` — сохранение собранных почт
- `lib/kv.ts` — обёртка над Upstash Redis

## Что нужно сделать перед запуском

### 1. Установить зависимости

```bash
npm install
```

### 2. Режим сайта — всё бесплатно или платно

Сейчас сайт настроен так, что **все киты бесплатны** — вместо "добавить в корзину" человек просто
вводит почту и сразу получает ссылку на скачивание (та же механика double opt-in, что была у
`/free`, только теперь работает для любого товара). Корзина и оплата при этом никуда не делись —
просто спрятаны, пока включён бесплатный режим.

Переключается одной переменной в `.env.local`:
```
NEXT_PUBLIC_SITE_MODE=free   # так сейчас — всё бесплатно, только почта
NEXT_PUBLIC_SITE_MODE=paid   # обычная корзина + оплата картой через Stripe
```
Ничего больше менять не нужно — переключили значение, пересобрали (`npm run build` на Vercel
сделает это сам при следующем деплое) — и весь сайт целиком переключается между режимами.

### 3. Подключить хранилище (products + собранные почты) — Redis через Vercel

Раньше товары были зашиты прямо в код (`lib/products.ts`, теперь удалён), и почты из `/free` просто попадали в
лог сервера, а не сохранялись. Теперь и то, и другое хранится в Redis-базе, и всем этим можно
управлять через `/admin` — без единой правки кода.

**Как подключить (2–3 минуты):**
1. В панели Vercel откройте ваш проект → вкладка **Storage** → **Create Database** → выберите
   **Redis** (провайдер — Upstash, это нормально, так теперь называется бывший «Vercel KV»).
2. Нажмите **Connect to Project** — Vercel сам добавит переменные `UPSTASH_REDIS_REST_URL` и
   `UPSTASH_REDIS_REST_TOKEN` в настройки проекта.
3. Для локальной разработки скопируйте эти же два значения в `.env.local` (можно вручную из
   вкладки Storage → ваша база → `.env.local` tab — там готовый блок для копирования).

**Без этого шага сайт всё равно работает** — просто использует встроенные 6 демо-китов
(`lib/seed-data.ts`) и не сохраняет почты на постоянку (только видно в логах сервера). Как только
подключите Redis — весь контент переезжает туда автоматически, ничего пересобирать не нужно.

### 4. Админка — `/admin`

Простая панель без наворотов, вход по одному паролю:

1. В `.env.local` задайте `ADMIN_PASSWORD` (просто пароль, любой) и `ADMIN_SESSION_SECRET`
   (случайная строка, `openssl rand -hex 32`).
2. Откройте `/admin` на сайте, введите пароль.
3. Внутри три вкладки:
   - **Products** — добавление/редактирование/удаление платных китов: название, цена, скидка,
     BPM, тональность, теги, описание, путь к обложке (`/covers/...`), путь к превью
     (`/previews/...`), и ссылка на сам ZIP-архив для скачивания.
   - **Free kit** — то же самое, но для бесплатного кита с `/free`.
   - **Leads** — список всех собранных почт (откуда пришли — бесплатный кит или подписка на
     рассылку, когда) с кнопкой «Download CSV» для выгрузки.

Обложки и mp3-превью физически всё ещё нужно класть в `public/covers/` и `public/previews/`
вручную (как раньше) — админка хранит только *путь* к файлу, не сам файл. Загрузку файлов через
саму админку можно добавить отдельно, если станет нужно — это следующий логичный шаг, когда
дойдёте до реальных обложек.

### 5. Настроить Stripe

1. Зарегистрируйтесь на [stripe.com](https://stripe.com) (принимает платежи и без юрлица есть тестовый режим — для реальных выплат понадобится подключить банк/ИП или Stripe Atlas в зависимости от страны).
2. Скопируйте `Secret key` из Dashboard → Developers → API keys.
3. Скопируйте `.env.example` в `.env.local` и вставьте ключ:
   ```bash
   cp .env.example .env.local
   ```
4. Локально проверить оплату можно тестовой картой `4242 4242 4242 4242`, любой будущей датой и любым CVC.

### 6. Загрузить сами файлы (ZIP с WAV/MIDI)

Файлы с аудио — тяжёлые, поэтому их не кладут в код сайта. Варианты:

- **Простой:** загрузите ZIP-архивы в любое приватное облачное хранилище (Cloudflare R2, AWS S3, Backblaze B2) и получите приватные/подписанные ссылки. Вставьте их в поле "Download URL" в `/admin` у нужного товара.
- **Для небольших паков:** можно положить архивы прямо в проект в папку `private-files/` (не в `public/`, чтобы их нельзя было скачать напрямую) — код для этого варианта уже есть закомментированным внизу `app/api/download/route.ts`.

Пока ссылки не настоящие — на странице успеха кнопка скачивания вернёт ошибку "файл ещё не загружен".

### 7. (Опционально) Бесплатный кит за почту — `/free`

Страница `/free` — лид-магнит в духе Rekonise, но с **double opt-in**: человек вводит почту →
получает письмо со ссылкой «подтвердить и скачать» → файл открывается только после клика по
ссылке. Так фейковые/несуществующие почты просто никогда не получат письмо и не смогут скачать —
это единственный надёжный способ отсечь мусорные адреса (сравнение с альтернативой — мгновенной
выдачей без проверки — было в чате, если нужно вспомнить логику).

- Без настроенного Resend (`RESEND_API_KEY`) сайт **не может** отправить письмо, поэтому в этом
  случае автоматически включается запасной вариант — мгновенная выдача на экране без проверки
  почты (чтобы страница не была мёртвой). Как только подключите Resend — double opt-in включится
  сам, без правок кода.
- Не забудьте `EMAIL_TOKEN_SECRET` в `.env.local` — этим ключом подписываются ссылки-подтверждения
  (просто случайная длинная строка, сгенерировать: `openssl rand -hex 32`).
- Файл самого бесплатного пака — так же, как остальные, указывается через `/admin` → вкладка Free kit → поле "Download URL".
- Чтобы реально отправлять письмо и копить список подписчиков, нужен сервис рассылок. Сейчас подключён [Resend](https://resend.com) — бесплатный тариф достаточен для старта:
  1. Зарегистрируйтесь на resend.com, подтвердите домен отправки (или используйте их тестовый домен на старте).
  2. Скопируйте API key → впишите в `.env.local` как `RESEND_API_KEY`.
  3. (Опционально) создайте Audience (список подписчиков) в Resend → впишите его id как `RESEND_AUDIENCE_ID`, чтобы почты сразу копились в список.
  4. Впишите адрес отправителя в `RESEND_FROM`, например `iloveubetrayed <hello@вашдомен.com>`.
- Хотите другой сервис (Mailchimp, ConvertKit, Beehiiv) — вся логика в одном файле `lib/resend.ts`, там всего два метода (`addContact`, `sendKitEmail`), их легко переписать под другое API.
- Внизу страницы `/free` — блок с кнопками на соцсети («бонус, подпишись») — это честная механика без принуждения, поменяйте ссылки на свои в `app/free/page.tsx` (`SOCIALS`).

### 8. Email после оплаты (для платных заказов)

`app/api/webhook/route.ts` — заготовка для отправки письма со ссылками на скачивание, если
человек закрыл вкладку до того, как увидел страницу успеха. Нужно:
1. Подключить провайдера письма (Resend, Postmark, SendGrid).
2. Добавить вебхук в Stripe Dashboard → Developers → Webhooks, URL: `https://вашдомен.com/api/webhook`, событие `checkout.session.completed`.
3. Вставить `STRIPE_WEBHOOK_SECRET` в `.env.local`.

Без этого шага сайт полностью работает — страница `/checkout/success` сама проверяет оплату и
показывает ссылки на скачивание.

### 9. Запуск локально

```bash
npm run dev
```

Откройте http://localhost:3000

### 10. Деплой на Vercel

1. Залейте проект в GitHub.
2. На [vercel.com](https://vercel.com) → New Project → выберите репозиторий.
3. В настройках проекта добавьте те же переменные окружения, что в `.env.local` (`UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`, `STRIPE_SECRET_KEY`, при необходимости `STRIPE_WEBHOOK_SECRET`, `RESEND_API_KEY`, `RESEND_AUDIENCE_ID`, `RESEND_FROM`, `EMAIL_TOKEN_SECRET`, `NEXT_PUBLIC_SITE_URL` — впишите финальный домен). Если создавали Redis-базу через вкладку Storage прямо в этом проекте — первые два уже будут добавлены автоматически.
4. Deploy.

## Что поменять под себя

- **Название и бренд сайта** — `iloveubetrayed`, меняется в `components/Header.tsx`, `app/layout.tsx` (metadata) и `components/Footer.tsx`. Это про сам сайт, не про товары.
- **Название, цена, обложка, превью конкретного товара** — теперь через `/admin` → вкладка Products, без правки кода (см. раздел 3 выше). `lib/seed-data.ts` — это только стартовый набор на случай, если Redis ещё не подключён; после подключения редактируйте всё через админку.
- **Обложки паков** — файл картинки кладёте в `public/covers/`, в админке в поле "Cover image path" указываете `/covers/имя-файла.jpg`.
- **MP3 для тизера при наведении** — файл кладёте в `public/previews/`, в админке в поле "Preview mp3 path" указываете `/previews/имя-файла.mp3`.
- **Товары** — управляются через `/admin`; `lib/seed-data.ts` — только стартовый набор на случай, если Redis ещё не подключён.
- **Шрифт** — сейчас Jost (тонкие/лёгкие начертания) — бесплатный аналог примерно того же стиля, что у показанного вами референса (тонкий геометричный sans с широким трекингом). Если купите лицензию на Atyp Kido или другой шрифт — инструкция по подключению есть в начале `app/globals.css`.
- **Цвета** — сейчас светлая тема (кремовый фон, розово-сиреневый градиент в заголовках) — токены в `tailwind.config.ts` (`pink`, `pink2`, `cream`, `ink`...).
- **Избранное (сердечко)** — хранится в браузере через localStorage, у каждого посетителя своё, ничего никуда не отправляется.
- **Скидка за объём** — сейчас 10% при 3+ китах в корзине, настраивается константами `BUNDLE_MIN_QTY` / `BUNDLE_DISCOUNT` в начале `app/api/checkout/route.ts`. Поставьте `BUNDLE_DISCOUNT = 0`, чтобы выключить.

## Ограничения текущей версии

- Лицензионное соглашение / условия использования — в футере сейчас просто текст-заглушка, добавьте отдельную страницу `/license`, если нужно.
- Без личного кабинета — доступ к файлам даётся только через ссылку `session_id` сразу после оплаты (плюс опционально по email). Для истории покупок понадобится настоящая база данных и авторизация — это можно добавить отдельно, если станет нужно.
